# Ресурсы и брендовые файлы

| Ресурс | Расположение | Использование |
|---|---|---|
| Логотип и его SVG-path `#logoPath` | `assets/brand/logo.svg` | favicon, Open Graph, внешняя SVG-ссылка для знаков и геометрия Canvas через `Path2D` |
| Дизайн-токены и правила бренда | `brand-spec.md` | цвет, типографика, анимация, правила применения логотипа |
| SVG сцены и узлов | генерируются Canvas/UI-кодом | зависят от размера окна, состояния и анимации; отдельных исходных файлов не имеют |
| Шрифты | Google Fonts ссылки в `index.html` | загружаются удалённо; локальные копии в репозитории не хранятся |

Исходный SVG один: и legacy-лендинг, и Mini App ссылаются на `assets/brand/logo.svg`.
Сцена получает `d` того же `#logoPath` запросом файла и создаёт `Path2D`; путь больше не
дублируется внутри HTML. При замене формы нужно обновить этот SVG и сохранить `viewBox`
`0 0 499 499` и идентификатор `logoPath`.

`Dockerfile` копирует каталог `assets/` целиком в web-образ. Локальный fixture-сервер
раздаёт SVG с `image/svg+xml`. Для проверки UI важно открывать страницу через HTTP(S), а не
`file://`: загрузка отдельного SVG через `fetch` ограничивается политикой браузера.

Перед добавлением больших растровых файлов, шрифтов или видео сначала задать владельца,
исходник, лицензию, размер/формат и кэширование. Сейчас такого asset pipeline в проекте нет.
