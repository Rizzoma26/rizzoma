## Возможности

- `.codex/config.toml` задаёт Medium; High выбирайте для сложной архитектуры/миграции/дефекта. Явная настройка UI может переопределять default.
- Browser по умолчанию выключен. Для UI smoke, network/console, visual или browser-dependent E2E сначала сообщите о необходимости Browser; временно включите один существующий механизм в проекте, проверьте доступность и после задачи восстановите настройки. Playwright CLI не требует Browser plugin сам по себе. Computer Use и Unified Computer Use остаются OFF; не включайте их вместе с Browser. Legacy `node_repl` также отключён: если выбранный Browser действительно требует его, включайте только после проверки зависимости, сохраняя настоящий transport.
- Hosted connectors отключены через `features.apps = false`; локальный `codex-app-tools` не отключён. Временно подключайте только capability, которой требует задача. Не создавайте MCP-блоки без транспорта и не устанавливайте plugins автоматически.
- Context7, если уже доступен, используйте для актуального API конкретной библиотеки, которого не хватает в коде. Иначе точечно читайте официальную документацию. Для понятной локальной правки документационный поиск не нужен.
- GitLab допустим только для явно заданного MR/issue/CI/remote workflow Rizzoma, если такой remote действительно используется. По предыдущему аудиту remote — GitHub; GitLab MCP не нужен по умолчанию. Корпоративные интеграции сюда не подключаются.
- Superpowers выключен; подключение по явной необходимости для крупной feature, сложного refactoring/TDD/debugging не заменяет проектные skills для мелких задач.

## Передача ветки другому исполнителю

1. Из корня репозитория проверьте `git status --short` и актуальность инструкций в `AGENTS.md`.
2. Обновите краткий снимок ветки командой `npm run handoff`. Он записывает имя ветки, HEAD, upstream и список изменённых путей в `docs/handoffs/branch-context.md`; исходники, diff-содержимое и значения env в снимок не попадают.
3. Откройте [индекс документации](index.md), прочитайте текущую карту проекта, актуальные решения и критерии проверки. Сверьте, что `AGENTS.md`, проектные skills, документация и исходный код включены в планируемый коммит.
4. Проверьте generated snapshot после подготовки staged diff. Команда не добавляет файлы и не отправляет ветку. Секреты, IDE-файлы, локальные настройки и временные артефакты остаются вне handoff.

Снимок фиксирует состояние до commit. После новых изменений или перед следующей передачей запустите генератор повторно.
