# Бета: конфигурация контура вместо `beta_settings`

Журнал переноса настройки беты из таблицы `beta_settings` в серверный модуль
(скиллы `.agents/skills/beta-config-00…05`). Вынос статических данных сцены (`06`) —
в [`assets.md`](assets.md).

## 00. Решение

**Вариант B — перенос.** Бета меняется вместе с релизом, а не через админку. Решение принял
владелец 2026-09-29 в ответ на вопрос скилла 00.

Почему это продуктовое изменение, а не чистка БД: раньше dev-админ (при `QA_ENABLED=true`)
переключал туман в панели без деплоя. Теперь список меняется правкой `BETA_OPEN` в env
контура и пересозданием бота. В prod штатного пути изменения не было и раньше: `QA_ENABLED`
там запрещён, менять можно было только прямым SQL.

Подрешения (значения по умолчанию из скилла 00):

| Вопрос | Решение |
|---|---|
| Откуда значение контура | переменная `BETA_OPEN` в env-файле контура |
| Способ менять бету в dev без деплоя | нет; пересоздание бота с новым env |
| Дубликаты, пустой элемент, пустой список | ошибка запуска, не нормализация |
| Поставка | две: сначала код без обращений к `beta_settings`, затем миграция `003` |
| Админ-панель | переключатель убран, список открытых узлов показывается только для чтения |

## 02. Эффективные значения dev и prod

Эффективное значение — строка `beta_settings` (id = 1): её отдавал `/api/state`. Env и
`economy.js` использовались только при первом создании строки.

| Контур | Как получено | Таблица есть | Значение в БД | Менялось админом | `updated_at` | `BETA_OPEN` в env | По умолчанию | Эффективное | Дата |
|---|---|---|---|---|---|---|---|---|---|
| dev | **выведено, не измерено** | не проверено | не прочитано | не проверено | — | пусто в `docker/dev.env.example` | `0,1,3,4` | `0,1,3,4` | 2026-09-29 |
| prod | **выведено, не измерено** | не проверено | не прочитано | не проверено | — | пусто в `docker/prod.env.example` | `0,1,3,4` | `0,1,3,4` | 2026-09-29 |

Почему не измерено: у сессии, выполнявшей перенос, нет доступа к серверу, env-файлам
`/etc/rizzoma/*.env` и БД контуров, а по [`environments.md`](environments.md) реальное
развёртывание ещё не выполнено. Выведенное значение записано в шаблоны
`docker/dev.env.example`, `docker/prod.env.example` и `.env.example`.

**CONTRADICTION** — наблюдаемое / документированное / предлагаемое: наблюдать значения
контуров не удалось; шаблоны раньше оставляли `BETA_OPEN` пустым; предлагается перед
выкладкой кода из этой ветки снять настоящее значение каждого контура командой ниже и
записать в env контура именно его. Особенно важно для dev: если админ менял туман в панели,
значение в БД отличается от `0,1,3,4`.

```bash
tools/beta-settings-capture.sh /etc/rizzoma/dev.env
tools/beta-settings-capture.sh /etc/rizzoma/prod.env   # только с согласия владельца
```

Скрипт только читает: SQL идёт в read-only транзакции (`tools/beta-settings-capture.sql`), env
не меняется. Печатает применённые миграции, строку `beta_settings` (значение, «менялось
админом: да/нет» без id администратора, `updated_at`), статус переменных и готовую строку
`BETA_OPEN=…`. Расхождения помечает `CONTRADICTION`:

- в БД порядок или повторы отличаются от нормализованного списка — модуль отдаёт индексы по
  возрастанию без повторов;
- env расходится с БД — действует значение БД, его и сохранить.

Если в БД пустой список, скрипт завершается с кодом 3: клиенты такой ответ игнорировали и
держали свой кэш, поэтому значение для контура выбирает владелец. Env-файл правится вручную
после подтверждения владельца: сначала `cp -p` на резервную копию, затем
`docker compose --env-file … config --quiet`. Контейнеры до выкладки кода не пересоздавать.

Скрипт проверен на одноразовом PostgreSQL 16 с миграциями `001`–`002` (строка есть, строки
нет, пустой список, env расходится с БД) через заглушку `docker compose`; на живых контурах
не запускался.
