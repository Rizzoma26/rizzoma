# Передача контекста ветки

Цель — чтобы коллега после clone/pull получил правила, решения, карту кода и проверяемое
состояние ветки из Git, без доступа к истории чата или локальной машине автора.

## Что включать в ветку

1. Изменённый исходный код, SQL-миграции, конфигурационные шаблоны и релевантные тесты.
2. `AGENTS.md` и проектные `.agents/skills/*/SKILL.md`, на которые ссылается AGENTS.
3. Текущую документацию: особенно `docs/index.md`, `project-guide.md`, `data-and-idempotency.md`,
   `review-baseline.md`, требования и принятые решения.
4. Снимок `docs/handoffs/branch-context.md`, созданный командой `npm run handoff` перед
   подготовкой коммита. Он связывает git-состояние с уже сохранёнными документами.

Не копируйте в handoff секреты, файлы `.env`, токены, initData, платёжные данные, дампы БД,
локальные рабочие файлы IDE, резервные копии `.bak`, содержимое `.superpowers/`, локальные
настройки `.codex/` и `docs/codex-*` audit-артефакты с абсолютными путями хоста. Значения
окружения не нужны для понимания архитектуры; используйте только `.env.example` и описания из
`docs/environments.md`.

## Сборка handoff

Из корня проекта выполните:

```bash
npm run handoff
```

Генератор использует локальные Git metadata, не обращается к remote, не читает diff-содержимое,
env-файлы и БД. Он записывает ветку, HEAD, upstream, staged/unstaged/untracked пути и показывает,
какие обязательные документы пока не отслеживаются Git. Локальные и потенциально секретные пути
не перечисляются, выводится только их число и количество уже staged локальных путей. Если это
число ненулевое, остановитесь и проверьте обычный `git status` до commit.

После генерации:

1. Прочитайте список изменений и решите, какие файлы относятся к задаче.
2. Вручную добавьте нужные файлы в Git; просмотрите staged diff и проверьте, что секреты не попали.
3. Сверьте, что инструкции, документация, код и результаты проверок соответствуют одному состоянию.
4. Создайте commit и отправляйте ветку только своим обычным согласованным способом.

Команда не делает `git add`, commit, push, тестовый запуск или Docker Compose. Снимок отражает
состояние на момент генерации; после новых правок выполните её ещё раз.

## Источники истины для нового исполнителя

1. `AGENTS.md` задаёт постоянные правила и ограничения.
2. `docs/index.md` маршрутизирует к нужному документу; `README.md` даёт обзор продукта.
3. Реализация и новые SQL-миграции показывают текущее поведение. Применённые миграции не менять.
4. Исторические prompt-файлы сохраняют происхождение требований; используйте `prompt-analysis.md`
   и `user-stories.md`, чтобы понять, что осталось актуальным.
5. `world-map-*` — будущая спецификация, а не код текущего Mini App.
6. Внешнее состояние Telegram, PostgreSQL, секреты и deployment не восстанавливаются из Git;
   runtime-готовность нельзя выводить только из шаблонов.
