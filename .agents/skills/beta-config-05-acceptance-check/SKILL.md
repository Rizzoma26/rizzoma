# Скилл 05 — приёмка переноса беты

**Запуск:** «выполни скилл `beta-config-05-acceptance-check`». **Требует:** решение B; результаты скиллов 01, 03, 04 и таблицу эффективных значений из `.agents/skills/beta-config-02-capture-values/SKILL.md`. **Меняет:** только тесты (новые файлы, если их ещё нет). Код, БД и контуры не менять.

## Цель

ТЗ, п. 5 — три утверждения, каждое проверяется отдельно:

1. API отдаёт прежний список.
2. Некорректная конфигурация останавливает запуск с понятной ошибкой.
3. Права доступа и состояние пользователей не меняются.

## Предусловия

**Стоп-условия:**
- Нет таблицы из скилла 02: без эталона «прежний список» подтвердить нечем.
- Скиллы 01, 03 или 04 не завершены, либо их тесты не зелёные.
- Для проверки потребовалось подключиться к dev или prod: этот скилл работает на тестовых окружениях и одноразовой БД. Живые контуры — только по отдельной просьбе владельца.

## Проверка 1. API отдаёт прежний список

Эталон — эффективное значение контура из скилла 02.

1. Тест по образцу `tests/environment.bot.test.mjs`: импортировать `bot/bot.js` (отдельным query-суффиксом для dev и prod), выставить `BETA_OPEN` равным эталону, дёрнуть `/api/state` через ту же заглушку сервиса идентичности. Ожидается массив целых по возрастанию, равный эталону.
2. Проверить, что ответ следует за серверной настройкой: другое допустимое значение `BETA_OPEN` даёт другой ответ. Значение `betaOpen` в публичном `config.js` и содержимое `rizzoma_beta` в браузере на ответ сервера не влияют.
3. Клиент: после ответа `/api/state` `window.__RZ.beta()` (хук доступен при `?e2e=1`) равен эталону.
4. Порядок и формат. Если эталон из скилла 02 не отсортирован или содержит иной формат — это **CONTRADICTION**: модуль отдаёт по возрастанию.
5. Живой контур этим не доказывается. После выкладки на dev разрешённый тестер открывает настоящий Mini App и сверяет туман с эталоном; на prod — только с согласия владельца. До этого пункт в отчёте — «не проверено».

## Проверка 2. Некорректная конфигурация останавливает запуск

Тест запускает настоящий процесс: `spawn(process.execPath, ['<абсолютный путь>/bot/bot.js'], {cwd, env})`.

- `cwd` — временный пустой каталог, а `env` — только явно перечисленные переменные: `bot.js` импортирует `dotenv/config`, и без этого процесс мог бы подхватить реальный `.env` разработчика.
- Минимально валидное окружение под блок проверок `if(isEntry)`: `APP_ENV`, для dev непустой `DEV_ALLOWED_TG_IDS`, `PAYMENT_MODE=disabled`, `APP_URL` с `https://`, `CORS_ORIGIN` — тот же origin, синтетический `BOT_TOKEN`, `REGISTRATION_API_BASE` и `DATABASE_URL` с недостижимыми адресами. Пул `pg` подключается лениво, а проверка беты выполняется до `STORE.ready()`, поэтому сеть и БД не нужны.
- Неверные значения `BETA_OPEN`: `abc`, `0,abc`, `-1`, вне диапазона (равное `ECON.TIERS.length`), `1.5`, `0,,1`, `1,1`, `,`, а также пустое значение при включённом `required` (dev и prod).

Что проверять:

| Признак | Ожидается |
|---|---|
| Код выхода | не ноль |
| Сообщение | в stderr есть `BETA_OPEN`, первый плохой элемент или причина и допустимый диапазон |
| Утечки | нет значений других переменных (синтетический токен, `DATABASE_URL`) |
| Скорость | процесс завершается быстро, не ожидая сети и БД; сообщения об ошибке БД нет |
| Корректное значение | сообщения про `BETA_OPEN` нет (процесс упадёт позже на недостижимой БД — это ожидаемо) |

Контейнер: при плохом env бот выходит с кодом 1, а `restart: unless-stopped` перезапускает его по кругу; `web` зависит от здорового бота, и выкладка визуально «не поднимается». Это сигнал, а не сбой. Проверять на одноразовом стенде по `docker compose ps` и логам, из которых убраны значения env. На контурах не запускать.

## Проверка 3. Права доступа и состояние пользователей не меняются

### 3a. Права доступа

- Существующие тесты доступа проходят **без правок**: `tests/environment.bot.test.mjs` (матрица 401/403; `/api/admin/overview` — 200 в dev и 403 в prod), `tests/auth.test.mjs`, `tests/e2e/auth.spec.mjs`. Ослабить их ради зелёного результата нельзя.
- Ревью диффа: в `auth`, `adminAuth`, `validateInitData`, `QA_ENABLED`, `DEV_IDS`, `ADMINS` изменений нет; в `bot/bot.js` меняются только строки про бету.
- `/api/admin/tester` и `/api/admin/overview` работают по прежним правилам. `POST /api/admin/beta` теперь 404 для всех — единственное намеренное изменение поверхности (убрана запись).
- Проектный skill `security-review`: граница доверия сузилась; сообщения об ошибках не раскрывают значения env.

### 3b. Состояние пользователей

На одноразовой БД из `.agents/skills/beta-config-04-drop-migration/SKILL.md` (случай b) сравнить состояние до и после миграции, **не читая содержимое**:

- число строк в `users`, `participant_registrations`, `api_sessions`, `invoice_intents`, `payment_receipts`, `engagement_accounts`, `engagement_awards`;
- для таблиц с идентификатором uuid — ещё хэш упорядоченных идентификаторов;
- число отозванных доступов: `SELECT count(*) FILTER (WHERE access_revoked_at IS NOT NULL) FROM participant_registrations`.

Платёжные и персональные поля не читать и не выводить. Клиентские ключи `rizzoma_claims`, `rizzoma_me`, `rizzoma_engagement` не затронуты: зелёные `tests/client-state.test.mjs` и `tests/e2e/engagement.spec.mjs`.

## Отчёт

- По каждому из трёх утверждений: что проверено, чем (тест или команда), результат.
- **Не проверено:** настоящий Telegram и Mini App, реальные dev и prod, доставка обновлений Telegram, поведение при реальной выкладке.
- **CONTRADICTION**, если нашлись.
- Остаточные риски: первый кадр до ответа `/api/state` (скилл 03, шаг 10), окно совместимости при выкладке миграции (скилл 04).

## Чего не делать

- Не подключаться к dev и prod «для быстрой проверки», не применять миграции, не печатать секреты.
- Не считать зелёные unit- и e2e-тесты доказательством работы Mini App в Telegram — `docs/environments.md` прямо разделяет синтетические проверки и реальный запуск.
- Не менять код, чтобы проверка прошла: найденное расхождение — в отчёт, исправление — отдельным решением владельца.
