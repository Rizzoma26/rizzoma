# Скилл 01 — серверный модуль конфигурации беты

**Запуск:** «выполни скилл `beta-config-01-server-module`». **Требует:** решение B в `.agents/skills/beta-config-00-decision-gate/SKILL.md`. **Меняет:** новый `bot/beta-config.js`, `bot/bot.js` (чтение настройки и проверка при запуске), `Dockerfile` (стадия `bot`), примеры env, README, тесты. Таблицу `beta_settings` и её чтение/запись в этом скилле **не трогать** — источник истины переключает скилл 03.

## Цель

ТЗ, п. 1: завести серверный модуль конфигурации беты с валидируемым списком открытых узлов. Публичный клиентский `config.js` источником истины не использовать.

## Предусловия

**Стоп-условия:**
- Нет решения B из скилла 00.
- Ветка не `feat/app` (или потомок `ea5c530`) — в `main` нет бота с хранилищем.
- В репозитории уже есть `bot/beta-config.js` или файл `db/migrations/003_*` — не перезаписывать, разобраться, откуда они.
- `git status` показывает чужие несохранённые изменения в файлах из списка «Меняет» — согласовать с владельцем.

Проверки только на чтение:

```bash
git status --short && git branch --show-current
grep -n "parseList\|betaOpen\|STORE.beta\|isEntry" bot/bot.js
grep -n "location \^~ /api" docker/nginx.conf
grep -n "COPY.*bot" Dockerfile
```

Убедиться по `nginx.conf`, что `/api/` (кроме `/api/v1/`) идёт в бот, — значит, `/api/state` обслуживает бот, а модуль принадлежит `bot/`, а не TypeScript-API (`apps/api`, там уже есть свой `config.ts` на zod, но `/api/state` он не отдаёт).

## Решения, которые надо подтвердить до кода

| № | Вопрос | По умолчанию | Почему |
|---|---|---|---|
| D1 | Где модуль | `bot/beta-config.js`, ESM, как `storage.js` | `/api/state` в боте; `economy.js` подключать через `createRequire`, как в `bot.js` |
| D2 | Откуда значения контура | переменная `BETA_OPEN` в env контура | уже передаётся compose (`BETA_OPEN` у сервиса `bot`), описана в примерах env; значения контуров хранятся вне Git |
| D3 | Что считать ошибкой | нецелое, вне `0…N-1`, пустой элемент (`0,,1`), дубликат, пустой список | клиент **игнорирует** пустой список (`Array.isArray(betaOpen) && betaOpen.length`) — пустая бета молча оставила бы устаревший локальный кэш; дубликат чаще всего опечатка |
| D4 | Когда `BETA_OPEN` обязателен | в реализации модуля — параметр `required`; **включается в скилле 03**, когда модуль становится единственным источником | до этого источник — БД, и требовать env, который ничего не решает, нельзя |
| D5 | Когда проверять | в блоке `if(isEntry)` в `bot.js`, до `STORE.ready()` | импорт `bot.js` в тестах (`environment.bot.test.mjs`, `engagement.bot.test.mjs`) не должен падать; отказ до подключения к БД — быстрый и без побочных эффектов |

`N` брать как `ECON.TIERS.length` (сейчас 10), не числом.

## Шаги

1. **Модуль.** Создать `bot/beta-config.js` — чистые функции без обращения к сети и БД:
   - `parseBetaOpen(raw, {tierCount})` → `{ok:true, open:[…]}` (по возрастанию, без дубликатов) или `{ok:false, error}`;
   - `loadBetaConfig(env, {tierCount, defaultOpen, required})` → то же, плюс `source` (`'env'` или `'default'`); при незаданной переменной и `required:false` вернуть `defaultOpen` (копию `ECON.BETA_OPEN`).
   Пробелы вокруг элементов допустимы. Текст ошибки называет переменную `BETA_OPEN`, что именно не так (первый плохой элемент) и допустимый диапазон. Значения других переменных в сообщение не попадают.
2. **Подключение в `bot/bot.js`.** Заменить мягкий `parseList` на модуль. Проверку выполнить внутри `if(isEntry)` до `await STORE.ready()`: при `ok:false` — `console.error(error)` и `process.exit(1)`. Своё сообщение, не общее «Invalid environment, allowlist, origin, QA or payment configuration» — иначе непонятно, что именно исправлять. Остальные проверки этого блока не менять.
3. **Образ.** Стадия `bot` в `Dockerfile` копирует явный список файлов — добавить `bot/beta-config.js` в эту `COPY`, иначе контейнер упадёт на импорте. `.dockerignore` новый файл не исключает — проверить.
4. **Примеры env и README.** В `.env.example`, `bot/.env.example`, `docker/dev.env.example`, `docker/prod.env.example` описать формат (`0,1,3,4`) и что значение проверяется при запуске. Семантику «источник истины» здесь пока не менять — её меняет скилл 03. В README (таблица переменных) — то же.
5. **Тесты.** `tests/beta-config.test.mjs` на `node:test`, без сети: корректный список (порядок, пробелы), нецелое, отрицательное, вне диапазона (`N`), пустой элемент, дубликат, пустая строка при `required:true` и `required:false`, текст ошибки (есть `BETA_OPEN` и первый плохой элемент, нет посторонних значений).

## Проверки

```bash
node --test tests/beta-config.test.mjs
node --test tests/environment.bot.test.mjs tests/engagement.bot.test.mjs   # импорт bot.js не должен падать
npm test
docker compose --env-file <путь к env> config --quiet                        # без вывода секретов
docker compose --env-file <путь к env> build bot                             # только изменённый сервис
```

Сборка образа доказывает, что файл попал в образ; запуск контура и реальный Telegram этим скиллом не проверяются.

## Отчёт

Что создано и изменено; результаты проверок; принятые D1–D5; ограничения (контуры не запускались, `beta_settings` не тронута, источник истины пока БД).

## Чего не делать

- Не читать и не писать `config.js` / `CFG.betaOpen` на стороне сервера, не добавлять список беты ни в один публичный файл.
- Не печатать значения env; для проверки — имена и статус «задано / не задано».
- Не менять `002_persistent_bot_state.sql` и не добавлять миграции — это скилл 04.
- Не включать `required` в `bot.js` (скилл 03) и не менять `/api/state`, `/api/admin/*`, `storage.js`.
